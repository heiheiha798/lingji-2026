# 优化说明

## 优化思路

实现采用 64 位 bitset 的 blocked Warshall。每轮先在一个 64 x 64 子块内求
完整闭包，再据此生成 64 条闭包后的 pivot 行，最后用一个 kernel 将这 64
个 pivot 一次应用到所有行。块间仍严格保持 Warshall 的先后依赖，块内则把
原来 64 次全矩阵扫描和 kernel 启动合并为一次扫描，显著降低启动开销。

设备端直接把输入上传到闭包矩阵，不再额外保存一份邻接矩阵，也省去一次
device-to-device 全矩阵复制。临时存储仅包含 64 条 pivot 行和 64 个块内
可达 mask。

`BuildPivotRows` 生成的每条 pivot 行本身已经包含块内闭包。应用到普通行时
直接按该行原始 pivot bits 合并这些闭包行即可，不需要先通过 `pivot_masks`
再次扩张 mask。这样删除了一次串行 bitset 闭包、CTA barrier，并显著减少
SCC workload 中重复合并的 pivot 行数。

对于 `words<=256` 的结构化矩阵，Apply 使用单独编译的特化：当前行在 pivot
word 中没有 bit 时整 CTA 直接返回，不再扫描整行。更大的稠密闭包使用不含
该分支的特化，避免恒不命中分支污染主路径。

Apply 进一步利用块内 `pivot_masks` 压缩生成元：每个 warp 的 lane 0 贪心
选择一个 pivot 后，从 remaining mask 中直接删除该 pivot 在块内可达的所有
点，再将选出的 mask 广播给 warp。因为选中 pivot 的闭包行已经包含这些被
删除点的全部出边，所以结果不变；SCC 中常可把 64 条重复行合并缩减为 1 条。

CUDA 12.8 / GPU7 合法冷进程 baseline 的 P1 至 P5 为 369.442、645.194、
804.665、336.064、2059.116 ms；删除重复 mask 闭包后为 346.098、431.966、
777.112、330.967、1546.766 ms。随机五类功能测试全部通过。
加入小矩阵空行早退后，P1/P4/P5 的代表结果为 339.691、333.599、1549.635
ms；其中 P1 再缩短约 1.9%，大矩阵保持原有路径。
生成元压缩后 P1 至 P5 为 335.960、391.714、469.855、320.347、1346.662
ms，随机五类继续全部通过。
