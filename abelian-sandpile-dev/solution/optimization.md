# 优化说明

## 优化思路

实现保留双缓冲 Jacobi 稳定化，以保证任意尺寸和输入分布下的精确结果。
每个 sweep 仍批量处理当前高度中的全部合法倒塌次数，但只有 `q != 0` 的
格点才读写 64 位 odometer，避免稳定区域在数千轮传播中反复产生无效的
16-byte 读改写流量。

调用开始时精确扫描输入最大值。最大高度不超过 `UINT8_MAX` 或 `UINT16_MAX`
时，高度双缓冲分别全程使用 8 位或 16 位无符号整数，因为一次 Jacobi 更新
都满足 `3 + 4 * floor(TYPE_MAX / 4) = TYPE_MAX`，后续不会溢出；更高输入使用
32 位特化，同理保持 `UINT32_MAX` 上界。三条路径分别编译，不在 sweep 内
保留类型分支。公开 P1/P4 走 8 位路径，其余性能点走 16 位路径。

终止检测每 16 个 sweep 执行一次。稳定状态是 sweep 的不动点，因此额外
sweep 不会改变 stable 或 odometer；这一批处理减少了 device-to-host 标志
传输、stream 同步、清零和全局原子写。带终止检测和不带终止检测的 sweep
由编译期模板分别生成，普通 sweep 中不保留原子分支。满网格检测轮先用
warp ballot 聚合 active，再由每个活跃 warp 的一个 lane 更新全局标志；稀疏
包围盒仍让每个活跃 cell 直接更新，避免低密度时多余的 ballot 指令。

初始化时用 256 个等距 host 样本区分稠密雨与稀疏砂源。稠密输入直接使用
完整网格 Jacobi；稀疏输入在 GPU 初始化中归约初始不稳定格点的包围盒，双
缓冲均初始化为输入，并让计算区域每轮向外扩展一格。这样从未进入计算区域
的两份高度始终一致，同时不会漏掉相邻传播。包围盒达到全图后使用单独编译
的满网格 sweep，避免动态边界算术。

RTX 4090 物理 GPU 7 的完整公开单次验收中，随机 5 组与固定 6 组全部通过。
P1 至 P5 用时分别为 396.935、3970.809、6482.367、6512.743 和
24063.923 ms；相对随包 reference 的加速为 1.898x、3.815x、3.714x、
8.541x 和 3.956x。

在同一 CUDA 12.8 / GPU7 冷进程 candidate 口径下，本阶段 32 位高度基线
P1 至 P5 为 416.642、3985.955、6470.068、6492.416、24080.352 ms；包围盒
版本的代表结果为 434.290、3786.450、6496.776、6531.684、23296.750 ms。
其中稀疏局部点 P2/P5 分别缩短约 5.0%/3.3%，随机五类功能测试全部通过。
进一步启用 16 位高度后，P1/P2 的首轮结果为 391.016/1373.000 ms，P2 相比
包围盒 checkpoint 缩短约 2.76 倍。随机五类继续全部通过，另用包含
`initial=1000000` 的独立用例验证了 32 位特化的 stable 与 odometer。
加入 8 位特化后，P1/P4 进一步降至 362.921/4949.787 ms，分别比 16 位路径
缩短约 7.2%/4.9%。
三次冷进程消融中，P1 的 warp 聚合/逐 cell 原子中位数为 368.862/381.023
ms；P4 的代表结果从 4949.787 进一步降至 4790.227 ms。
